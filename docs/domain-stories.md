## 0. 이 문서를 읽는 법

### 0-1. 도메인 스토리텔링이란

기능 목록 대신 **구체적인 장면 하나**를 "누가 → 무엇을 → 어떻게 한다" 문장으로 이어 그린다.
문장에 나오는 명사가 **용어집**이 되고, 그 용어가 그대로 테이블·API·코드 이름이 된다.

### 0-2. 표기법

| 기호 | 뜻 | 예 |
|---|---|---|
| 👤 | 사람 액터 | 👤 지우 |
| 🖥️ 🤖 🔌 📰 | 시스템 액터 | 🖥️ Current, 🤖 크롤러, 🔌 OpenRouter, 📰 언론사 피드 |
| `[ ]` | 작업 객체 (주고받는 것) | `[샘플]`, `[실행 기록]` |
| ①②③ | 순서 | |
| ⚖️ | 이 단계에 걸린 **도메인 규칙** | |
| 🔀 | 분기·예외 | |
| 📝 | 이 단계가 남기는 **기록** | |

### 0-3. 범위

- **As-is(지금 있는 것):** 이야기 1
- **To-be(만들 것):** 이야기 2~7
- 모든 이야기는 **거친 단위**(화면 클릭 단위가 아니라 업무 단위)로 그렸다.

## 1. 등장인물과 작업 객체

### 1-1. 액터

| 액터 | 종류 | 하는 일 |
|---|---|---|
| 👤 **방문자** | 사람 | 로그인하지 않은 사람. 뉴스와 Hot은 볼 수 있지만 비교는 못 한다 |
| 👤 **사용자** (예: 지우) | 사람 | 로그인한 사람. 작업을 입력하고 비교하고 고른다 |
| 🖥️ **Current** | 시스템 | 이 서비스. 비교를 진행하고 기록을 남기고 순위를 계산한다 |
| 🤖 **크롤러** | 시스템 | GitHub Actions에서 12시간마다 돈다. 기사를 모으고 Hot을 판정한다 |
| 📰 **언론사 피드** | 외부 시스템 | TechCrunch, The Verge, Wired, Ars Technica, SiliconANGLE, MIT TR |
| 🔌 **OpenRouter** | 외부 시스템 | 여러 회사의 AI 모델을 하나의 API로 부를 수 있게 해 주는 중개 서비스 |
| 🧠 **판정 AI** | 외부 시스템 | 시스템 내부 판단용 AI(현재 Claude Haiku). 기사 분류, Hot 판정, 작업 유형 묶기 |

> 🔌 OpenRouter의 모델(= **실험 대상**)과 🧠 판정 AI(= **시스템의 도구**)는 다른 역할이다.
> 판정 AI 호출은 **실행 기록에 남기지 않는다.** 실험 데이터가 섞이면 순위가 오염된다. (규칙 R-24)

### 1-2. 작업 객체 (한눈에)

```
뉴스 쪽:   기사 ──묶임──▶ 사건(Hot)
비교 쪽:   작업 이름 ──묶임──▶ 작업 유형
           샘플 ──▶ 비교 ──▶ 실행(N개) ──▶ 선택 ──▶ 순위(계산)
연결:      사건(새 모델 출시) ──▶ 새 모델 추천 ──▶ 비교
```

정의는 [§9 용어집](#9-용어집)에 있다.

## 2. 이야기 1 — 뉴스가 Hot이 되기까지 *(As-is, 구현됨)*

> **장면:** 10월 13일 밤, Google이 Gemini 4 Argon을 공개했다. 다음 날 아침 9시(KST) 크롤이 돌고,
> 지우가 홈을 열자 맨 위에 "새 모델 · Google, Gemini 4 Argon 공개" 카드가 보인다.

| # | 누가 | 무엇을 | 어떻게 |
|---|---|---|---|
| ① | 🤖 크롤러 | `[기사]` | 📰 언론사 피드 6곳에서 가져온다 (피드당 최대 20건) |
| ② | 🤖 크롤러 | `[기사]` | 키워드로 1차 분류하고, 애매한 것만 🧠 판정 AI로 2차 분류한다 → **다룰 기사인가?** |
| ③ | 🤖 크롤러 | `[기사]` | 🧠 판정 AI로 **Hot인가?**를 판정한다 → 새 모델 / 긴급 / 아님 + 한 줄 이유 |
| ④ | 🤖 크롤러 | `[기사]` → `[사건]` | 최근 7일 사건 목록을 함께 보여주고, 같은 사건이면 같은 **사건 키**를 붙인다 |
| ⑤ | 🤖 크롤러 | `[기사]` | DB에 저장한다 (이미 있는 기사는 건너뜀) |
| ⑥ | 👤 방문자/사용자 | `[사건]` | 홈 맨 위 Hot 섹션에서 본다. 사건 하나 = 카드 하나 |
| ⑦ | 👤 방문자/사용자 | `[기사]` | 카드를 눌러 대표 기사(가장 먼저 나온 기사)를 읽는다 |

- ⚖️ **R-1** 분류("다룰 기사인가")와 Hot 판정("지금 주목할 기사인가")은 별개의 판단이다.
- ⚖️ **R-2** Hot 노출 기간은 사건의 **첫 기사 시각**부터 잰다. 새 모델 72시간, 긴급 48시간.
- ⚖️ **R-3** 판정 AI가 실패하면 Hot을 추측하지 않는다. 그 배치는 Hot 없이 넘어간다.
- 🔀 판정 AI 키가 없으면 → 분류는 키워드만으로 하고, Hot은 아무것도 붙지 않는다.
- 📝 `articles.hot_type`, `hot_reason`, `hot_event`

**Hot 종류 정의**

| 종류 | 포함 | 제외 |
|---|---|---|
| **새 모델** (`model_release`) | 모델 **자체**의 새 출시·메이저 버전 (GPT-6, Gemini 4) | 기존 모델 위의 새 UI·기능·에이전트, 루머, 벤치마크, 논문, 투자 |
| **긴급** (`breaking`) | 대규모 장애 · 모델/제품 종료 · 큰 가격·접근 변경 · 주요 AI 회사 인수합병 · **AI 오작동·피해** · **보안 사고·데이터 유출** · **개인정보·약관 변경** | 의견, 분석, 인터뷰, 제휴, 일반 투자, 회사 내부 연구·안전 조치 |

## 3. 이야기 2 — 작업을 입력하면 유형으로 묶인다 *(To-be)*

> **장면:** 지우는 자기소개서를 다듬고 싶다. 비교 화면에서 작업 이름 칸에 "자소서 다듬"까지 치자
> 자동완성에 "**문장 교정** · 128회 비교됨"이 뜬다. 지우는 그냥 "자소서 다듬기"라고 끝까지 입력한다.
> Current는 이것을 "문장 교정" 유형으로 묶는다. 지우 화면에는 계속 "자소서 다듬기"로 보인다.

| # | 누가 | 무엇을 | 어떻게 |
|---|---|---|---|
| ① | 👤 지우 | — | 로그인한다 (Google) |
| ② | 👤 지우 | `[작업 이름]` | 입력하기 시작한다 |
| ③ | 🖥️ Current | `[작업 유형]` 후보 | 입력한 글자로 기존 유형과 지우의 예전 작업 이름을 찾아 **자동완성**으로 보여준다 |
| ④a | 👤 지우 | `[작업 유형]` | 🔀 자동완성에서 하나를 고르면 → 그 유형으로 바로 정해진다 (⑤~⑦ 건너뜀) |
| ④b | 👤 지우 | `[작업 이름]` | 🔀 자유롭게 끝까지 입력하면 → ⑤로 |
| ⑤ | 🖥️ Current | `[작업 이름]` + `[기존 유형 목록]` | 🧠 판정 AI에게 "같은 유형이 있으면 그 유형을, 없으면 새 유형을" 묻는다 |
| ⑥ | 🧠 판정 AI | `[판정]` | 기존 유형 재사용 **또는** 새 유형 제안(이름·설명) |
| ⑦ | 🖥️ Current | `[작업 유형]` | 🔀 새 유형이면 유형 목록에 **추가**한다 → 다음 사람의 자동완성에 나타난다 |
| ⑧ | 🖥️ Current | `[작업]` | 지우의 작업(이름 "자소서 다듬기" → 유형 "문장 교정")으로 저장한다 |

- ⚖️ **R-4** 사용자에게는 **작업 이름**(자기가 쓴 말)을 보여준다. 순위·추천은 **작업 유형** 기준이다.
- ⚖️ **R-5** 유형 목록은 고정되어 있지 않다. 새로운 작업이 나오면 늘어난다.
- ⚖️ **R-6** 같은 사용자가 같은 작업 이름을 다시 쓰면 판정 AI를 부르지 않고 예전 결과를 재사용한다.
- ⚖️ **R-7** 유형이 너무 잘게 쪼개지지 않게 판정 AI는 **재사용을 우선**한다. 새 유형은 기존 어느 것과도 목적이 다를 때만 만든다.
- 🔀 판정 AI가 실패하면 → 임시로 "**미분류**" 유형에 넣고, 나중에 다시 묶는다. 비교는 막지 않는다.
- 🔀 비슷한 유형이 두 개 생겨 버리면(예: "문장 교정"과 "글 다듬기") → 관리자가 **병합**한다. 병합된 유형의 기록은 살아남는 쪽으로 합쳐 계산한다.
- 📝 `task_types`(새 유형일 때), `tasks`

> 💡 **같은 패턴이 두 번 나온다:** 기사→사건(이야기 1)과 작업 이름→작업 유형(이야기 2)은
> "여러 개를 의미로 묶고, 기존 묶음을 재사용한다"는 같은 구조다. → 아키텍처의 **의미 묶기** 패턴.

## 4. 이야기 3 — 블라인드 비교 *(To-be, 핵심)*

> **장면:** 지우가 "자소서 다듬기"에 자기소개서 한 문단을 붙여넣는다. Current가 "문장 교정"에서
> 쓸 기본 모델 3개(GPT·Gemini·Claude의 저가 모델)를 미리 골라 둔다. 지우는 "모델 이름 가리기"를 켜고 실행한다.
> 결과 A·B·C가 나오고, 지우는 B를 고른다. 그제야 B가 어떤 모델이었는지 공개된다.

| # | 누가 | 무엇을 | 어떻게 |
|---|---|---|---|
| ① | 👤 지우 | `[작업]` | 이야기 2로 작업을 정한다 |
| ② | 👤 지우 | `[샘플]` | 입력한다 (자기소개서 한 문단) |
| ③ | 🖥️ Current | `[추천 모델 3개]` | 작업 유형의 순위로 기본 3개를 골라 둔다. 🔀 순위 데이터가 없으면 임시 기본값 |
| ④ | 👤 지우 | `[모델 3개]` | 그대로 두거나 바꾼다 |
| ⑤ | 👤 지우 | `[블라인드 설정]` | "모델 이름 가리기"를 켜거나 끈다. 🔀 원하면 "고급 설정"에서 **추론 강도·최대 답변 길이**를 고른다 (기본은 모델 기본값) |
| ⑥ | 🖥️ Current | `[비교]` | 비교를 만들고, 3개의 **표시 순서를 무작위로 섞는다** |
| ⑦ | 🖥️ Current | `[샘플]` | 🔌 OpenRouter로 3개 모델에 **동시에** 보낸다 (서버 키 — 비용은 운영자 부담) |
| ⑧ | 🔌 OpenRouter | `[결과]` | 모델마다 결과를 돌려준다 |
| ⑨ | 🖥️ Current | `[실행 기록]` ×3 | 모델마다 남긴다: 실제 응답한 **모델 버전**, 입력·출력 토큰, 비용, 응답 시간, 표시 순서, 키 종류 |
| ⑩ | 🖥️ Current | `[결과]` ×3 | A·B·C로 보여준다. 블라인드면 이름·로고·비용을 가린다. **응답 속도는 블라인드여도 보여준다** |
| ⑪ | 👤 지우 | `[선택]` | 가장 나은 결과 하나를 고른다. 🔀 우열을 못 가리면 **"셋 다 비슷함"**, 다 마음에 안 들면 **"전부 별로"** |
| ⑫ | 🖥️ Current | `[선택]` | 기록한다. 그 뒤에 **모델 이름과 비용을 공개**한다 |
| ⑬ | 👤 지우 | — | 공개된 결과를 보고 끝내거나, 같은 샘플로 다시 비교한다 |

- ⚖️ **R-8** 블라인드 비교에서는 **선택하기 전까지 모델 이름(과 로고·비용)이 브라우저로 전달되지 않는다.** 화면에서 가리는 게 아니라 서버가 보내지 않는다. 응답 속도는 보낸다(사용자 결정).
- ⚖️ **R-9** 표시 순서는 매번 무작위다(위치 편향 방지). 섞인 순서는 실행 기록에 남긴다.
- ⚖️ **R-10** 비교 하나에 선택은 **한 번**만. 선택 후에는 바꿀 수 없다.
- ⚖️ **R-11** 실행 기록은 **수정·삭제하지 않는다**(추가만 한다). 모든 분석의 원천이기 때문이다.
- ⚖️ **R-12** 실행 기록에는 **요청한 모델 ID와 실제로 응답한 모델 버전을 둘 다** 남긴다. 같은 이름이라도 버전이 바뀌면 결과가 달라진다.
- ⚖️ **R-13** 비교는 만들 때의 **작업 유형을 그대로 기억한다**. 나중에 유형이 병합돼도 원래 값이 남는다.
- ⚖️ **R-27** 한 비교 안의 모델들은 **같은 설정**으로 돌린다. 기본은 아무 설정도 보내지 않는 것(모델 기본값)이고, 사용자는 추론 강도(기본·낮음·높음)와 최대 답변 길이(기본·짧게)를 고를 수 있다. 보낸 설정은 기록한다.
- ⚖️ **R-28** 모델에게는 **샘플을 그대로** 보낸다. 숨은 시스템 프롬프트를 붙이지 않는다. 사용자가 지시까지 샘플에 쓴다.
- 🔀 3개 중 하나가 실패(시간 초과, 오류)하면 → 나머지 2개로 비교를 계속한다. 실패도 실행 기록으로 남긴다.
- 🔀 2개 이상 실패하면 → 비교를 "실패"로 닫고 다시 시도하게 한다. 선택은 받지 않는다.
- 🔀 지우가 고르지 않고 나가면 → 비교는 "선택 안 함"으로 남는다. 실행 기록은 그대로 남지만 순위에는 쓰이지 않는다.
- 🔀 사용자의 하루 무료 비교(**5회**)를 다 쓰면 → "오늘 무료 비교가 끝났어요"라고 안내한다. (개인 키는 이야기 4)
- 📝 `samples`, `comparisons`, `runs` ×3, `choices`

## 9. 용어집

코드·DB에서는 오른쪽 영어 이름을 쓴다. **이 표에 없는 말을 새로 만들지 않는다.** 새 개념이 필요하면 이 표에 먼저 추가한다.

| 용어 | 영어(코드) | 정의 | 헷갈리기 쉬운 점 |
|---|---|---|---|
| **기사** | `article` | 크롤러가 모은 뉴스 한 건 | |
| **사건** | `hot event` | 같은 일을 다룬 Hot 기사 묶음. 사건 키(`hot_event`)로 식별 | 기사 ≠ 사건. 새 모델 추천의 출발점은 **사건** |
| **Hot 종류** | `hot type` | `model_release`(새 모델) / `breaking`(긴급) | |
| **모델** (브랜드) | `ai model` | Current의 Models 페이지에 있는 37개 브랜드 (ChatGPT, Gemini…) | 실행 단위가 아님. 카탈로그 모델과 구분 |
| **카탈로그 모델** | `catalog model` | OpenRouter에서 실제로 부를 수 있는 모델 하나 (예: `google/gemini-2.5-flash`). 가격·무료 여부 포함 | 브랜드 하나에 카탈로그 모델 여러 개 |
| **모델 버전** | `model version` | 실행 때 OpenRouter가 실제로 응답한 모델 식별자 | 요청한 ID와 다를 수 있다 → 둘 다 기록 |
| **작업 이름** | `task name` | 사용자가 자유롭게 쓴 작업 이름 ("자소서 다듬기") | 사용자에게 보이는 이름 |
| **작업 유형** | `task type` | 시스템이 의미로 묶은 작업 종류 ("문장 교정"). **순위의 단위** | 고정 목록 아님, 늘어남 |
| **미분류** | `unclassified` | 판정 AI 실패 시 임시 유형 | 나중에 다시 묶는다 |
| **작업** | `task` | 한 사용자의 작업 이름 + 그것이 묶인 작업 유형 | 사용자마다 따로 |
| **내 작업** | `saved task` | 저장해 둔 작업 + 대표 샘플 + 지금 쓰는 모델 | 새 모델 추천의 대상 |
| **샘플** | `sample` | 모델에 넣는 입력 한 개 | 본인만 볼 수 있음 |
| **비교** | `comparison` | 샘플 1개 × 모델 N개(기본 3)를 한 번에 돌려 고르는 한 회 | 비교 1번 = 실행 N번 |
| **실행** | `run` | 모델 1개에 샘플을 1번 보낸 결과와 측정값 | **모든 분석의 원천.** 추가만, 수정·삭제 없음 |
| **표시 순서** | `display position` | 비교 화면에서 그 실행이 놓인 자리(A·B·C) | 위치 편향 분석용 |
| **블라인드** | `blind` | 선택 전까지 모델 이름을 가리는 비교 | 서버가 이름을 안 보냄 |
| **선택** | `choice` | 비교에서 사용자가 고른 결과 | 비교당 1번, 변경 불가 |
| **순위** | `ranking` | 작업 유형별로 선택을 모아 계산한 모델 순서 | **저장 원본 아님** |
| **전체 순위** | `global ranking` | 모든 사용자의 선택 기준 | 처음 온 사람, 기본 추천의 근거 |
| **내 순위** | `my ranking` | 한 사용자의 선택만 기준 | 선택 10번 이상부터 표시 |
| **추천 모델** | `suggested models` | 비교 시작 시 미리 골라 둔 기본 3개 | 사용자가 바꿀 수 있음 |
| **새 모델 추천** | `new model suggestion` | 사건 × 카탈로그 모델 × 내 작업을 연결한 "비교해 보기" 제안 | 자동 실행 안 함 |
| **서버 키** | `server key` | Current의 OpenRouter 키. 허용 목록 모델용, 비용은 운영자 부담 | 브라우저 노출 금지 |
| **서버 키 허용 목록** | `server allowed` | 서버 키로 돌릴 수 있는 저가 모델 목록. 처음엔 `gpt-5-nano`, `gemini-2.5-flash-lite`, `claude-haiku-5.5` | 관리자가 정함 |
| **개인 키** | `user key` | 사용자 본인의 OpenRouter 키. 허용 목록 밖 모델용 | 보관 방식 보류 |
| **판정 AI** | `judge LLM` | 시스템 내부 판단용 AI (분류, Hot, 유형 묶기) | 실험 대상 아님 → 실행 기록에 안 남김 |
| **반복 묶음** | `repeat group` | 일관성 측정을 위해 같은 샘플·모델을 N번 돌린 실행들 *(3단계)* | 캐시 사용 금지 |

| R-23 | 허용 목록 밖 새 모델은 개인 키 흐름으로 | 비용 주체 |
| R-24 | 판정 AI 호출은 실행 기록에 넣지 않는다 | 실험 데이터 오염 방지 |
| R-25 | 서버 키는 허용 목록 모델만 | 운영자 비용 통제 |
| R-26 | 서버 키 기본 단위를 넘는 "복잡한 작업"은 개인 키 (반복 측정 하루 1회·샘플 2개까지는 서버 키) | 맛보기는 무료, 그 이상은 사용자 부담 |
| R-27 | 한 비교 안의 모델은 같은 설정. 기본은 모델 기본값, 사용자가 추론 강도·답변 길이 선택 가능 | 공정성 + 실제 사용과 같은 상태 |
| R-28 | 샘플을 그대로 보낸다 (숨은 시스템 프롬프트 없음) | 실제 사용과 같게, 숨은 영향 없게 |

## 11. 도메인 이벤트

"~가 일어났다"로 표현되는, 다른 부분이 반응할 수 있는 사실들. 지금은 별도 이벤트 시스템 없이 **DB 기록**이 곧 이벤트다.

| 이벤트 | 일어나는 곳 | 반응하는 곳 |
|---|---|---|
| **기사가 수집됨** | 크롤러 | Hot 판정 |
| **사건이 생김** (새 모델 / 긴급) | 크롤러 | 홈 Hot 섹션, 새 모델 추천 |
| **카탈로그에 새 모델이 보임** | 카탈로그 동기화 | 새 모델 추천 |
| **작업 유형이 생김** | 작업 | 자동완성 |
| **작업 유형이 병합됨** | 관리자 | 순위 계산 |
| **실행이 끝남** (성공/실패) | 실행 | 비교 화면 |
| **선택됨** | 비교 | 순위 계산, 추천 모델 |
